Stop retrying. Start correcting.

A small Python framework that catches an agent's bad output with executable checks and hands it a specific fix, instead of re-rolling the dice and hoping.

▶ Watch the loop repair itself Read the write-up GitHub

The problem

When an LLM step fails in a pipeline it rarely crashes. It returns a plausible wrong answer: right JSON shape, right field names, and a "total" that is really the pre-discount amount. Nothing throws, and you find out weeks later from a reconciliation report. A plain retry gives the agent no new information, so it tends to make the same mistake again.

How it works

  1. Generate: the engine produces a candidate answer.
  2. Validate: deterministic checks (schema, money math in Decimal, SQL actually executed, UI actions replayed) emit structured violations.
  3. Critique: a critic turns each violation into targeted repair instructions.
  4. Repair: the engine retries with that feedback, up to a fixed budget. If it still fails, it fails loudly with the best attempt.

The engine never sees raw violations, only the critic's feedback. Validation stays mechanical.

See it in 30 seconds

$ python3 -m selfcorrect demo --domain sqlq
Attempt 1/2
  WRONG_ROW_COUNT │ sql │ 2 -> 1
  Feedback: The query runs but returns 1 rows where 2 are expected.
            A WHERE condition is probably missing, wrong, or an
            unrequested LIMIT is cutting rows off.
Attempt 2/2
  violations: none

Why use it

Zero runtime dependencies

Pure Python 3.12+. The default engine runs offline with no API keys.

Pluggable engines

Simulated, local Hermes via Ollama, or Claude through the Anthropic API.

Three domains included

Invoices, text-to-SQL, and computer use, each a plug-in behind one registry.

Ships as a Claude skill

The loop's protocol is installable from skills/self-correct.

Get started

git clone https://github.com/sugeerth/self-correcting-agents
cd self-correcting-agents
python3 -m venv .venv && source .venv/bin/activate
python3 -m pip install -e .
python3 -m selfcorrect demo --domain sqlq
